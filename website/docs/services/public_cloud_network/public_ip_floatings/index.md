## `UPDATE` examples

<Tabs
    defaultValue="update"
    values={[
        { label: 'update', value: 'update' }
    ]}
>
<TabItem value="update">

Replaces the floating IP's target specification as a whole. The body carries the complete desired state of every field `publicCloud.publicIp.FloatingIPUpdateTargetSpec` exposes, which today is `description` alone. `description` is optional: restate it to keep it, and leave it out to clear it. This is how a description is removed. There is no separate delete.&lt;br /&gt;&lt;br /&gt;The create-only field `location` cannot be changed once the floating IP exists. It is deliberately absent from the update model, and sending it is rejected with a 400.&lt;br /&gt;&lt;br /&gt;The optional `checksum` guards against a lost update: when supplied it must match the floating IP's current checksum or the request is rejected with a 409 checksum mismatch. Omitting it skips the check and forces the write (last-write-wins).

```sql
UPDATE ovh.public_cloud_network.public_ip_floatings
SET 
checksum = '{{ checksum }}',
target_spec = '{{ target_spec }}'
WHERE 
id = '{{ id }}' --required
AND project_id = '{{ project_id }}' --required unless OVH_CLOUD_PROJECT_SERVICE is set
AND target_spec = '{{ target_spec }}' --required
RETURNING
id,
checksum,
created_at,
current_state,
current_tasks,
resource_status,
target_spec,
updated_at;
```
</TabItem>
</Tabs>
